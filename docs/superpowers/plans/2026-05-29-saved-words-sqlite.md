# Saved Words SQLite Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a persistent SQLite-backed saved-words list that can be toggled from the word popover and displayed to the right of the video player.

**Architecture:** Rust owns SQLite persistence through a new top-level `saved_words` module and Tauri commands. React owns in-memory saved-word UI state, the right panel, and save/remove controls inside the existing word lookup popover. Dictionary lookup remains separate and is reused only as metadata for saved-word payloads.

**Tech Stack:** Tauri 2, Rust, `rusqlite` with bundled SQLite, React 19, TypeScript, Vitest, React Testing Library, Tailwind CSS utility classes.

Serialize errors as:

```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum SavedWordsError {
    Unavailable,
    InvalidSavedWord,
}

impl SavedWordsError {
    pub fn kind(self) -> &'static str {
        match self {
            SavedWordsError::Unavailable => "saved-words-unavailable",
            SavedWordsError::InvalidSavedWord => "invalid-saved-word",
        }
    }
}

impl From<SavedWordsError> for String {
    fn from(value: SavedWordsError) -> Self {
        let message = value.kind();
        serde_json::json!({ "kind": message, "message": message }).to_string()
    }
}
```

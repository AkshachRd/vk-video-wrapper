# Авто-теги для сохранённых слов через Apple Intelligence — дизайн

Дата: 2026-06-16

## Цель

Автоматически подбирать **тематические** теги (тема/домен: еда, спорт, право,
эмоции и т.п.) для сохранённого слова, используя локальную модель Apple через
`tauri-plugin-apple-intelligence`. Это надстройка над существующей системой тегов
([[2026-06-16-word-tags-design]]): теги остаются единым набором, авто-теги не
отличаются от ручных, всё уже имеющееся (фильтр, автоподсказки, снятие,
каскадное удаление) переиспользуется без изменений.

## Решения (зафиксировано на брейншторме)

- **Что в тегах:** только тематические категории (тема/домен), 1–2 тега на слово,
  по-русски, нижним регистром. Часть речи/уровень/регистр — вне скоупа.
- **Когда:** автоматически в фоне при первом сохранении слова. Без кнопок и
  ручной перегенерации.
- **Связь с ручными тегами:** один общий набор, авто-теги неразличимы от ручных.
  `origin` не храним.
- **Платформа:** фича доступна только на macOS (Apple Intelligence). На
  Windows/Android — тихий no-op; ручные теги работают везде.

## Архитектура: гибрид (вызов модели в JS, логика в Rust)

Важное ограничение плагина: его Rust-API приватный (`mod commands`, без
`pub use`), наружу торчат только `init()`, `Error`, `Result`. Вызвать
`generate()` / `availability()` из своей Rust-команды нельзя, и в Tauri нет
обобщённого «позвать команду из Rust». Поэтому **сам вызов модели возможен только
из фронтенда** через npm-пакет `tauri-plugin-apple-intelligence-api`.

Гибрид сохраняет дух «логика в Rust»: фронт делает лишь неизбежный JS-вызов
модели, а вся ценная (и тестируемая) логика — построение промпта, парсинг,
валидация, дедуп, вставка — живёт в Rust.

Поток при первом сохранении слова:
1. (JS, фон) `build_word_tag_prompt(wordId)` — Rust-команда строит промпт.
   Возвращает `None`, если слова нет или у него уже есть теги (skip).
2. (JS) `generate(prompt)` из `tauri-plugin-apple-intelligence-api` — инференс.
3. (JS, фон) `apply_generated_tags(wordId, raw)` — Rust-команда парсит ответ,
   валидирует, вставляет 1–2 тега и возвращает обновлённый список тегов слова.
4. (JS) обновлённые теги подмешиваются в карточку.

Отклонены: чистый бэкенд (вариант A — недостижим, Rust-API приватный), чистый
фронт (вариант B — парсинг/валидация уехали бы в TS, дублируя бэкенд-логику),
форк плагина (вне скоупа MVP).

## Данные и бэкенд

### Платформенный гейтинг

В `src-tauri/Cargo.toml` плагин подключается только под macOS:

```toml
[target.'cfg(target_os = "macos")'.dependencies]
tauri-plugin-apple-intelligence = { git = "https://github.com/jaytuduri/tauri-plugin-apple-intelligence" }
```

Плагин регистрируется в `lib.rs` под `#[cfg(target_os = "macos")]`
(`.plugin(tauri_plugin_apple_intelligence::init())`) — только чтобы JS-команды
плагина работали на macOS. Наши собственные команды плагин не вызывают и от него
не зависят, поэтому `build_word_tag_prompt` / `apply_generated_tags` компилируются
на всех платформах одинаково.

На не-macOS плагин не зарегистрирован: JS-вызов `availability()` отклонится,
фронт это ловит и считает таггер недоступным. Никаких Rust-заглушек не нужно.

JS-команды плагина требуют разрешения в capability. В
`src-tauri/capabilities/default.json` добавляется permission плагина (идентификатор
вида `apple-intelligence:default` — точная строка сверяется по README плагина на
момент реализации).

### Доступность

Отдельной бэкенд-команды нет. Доступность фронт узнаёт прямым JS-вызовом
`availability()` (возвращает `{ available: bool, reason?: string }`). На не-macOS
вызов отклоняется → трактуем как `available = false`.

### Хранение

Отдельной схемы нет. Авто-теги — обычные строки в существующей `word_tags`,
вставляются тем же кодом, что и ручные теги. `origin` не храним. Следствие:
фильтр, автоподсказки, снятие крестиком и каскадное удаление работают для
авто-тегов автоматически, без изменений.

### Когда генерируем

Только при **первом** сохранении нового слова:
- `save_word` — upsert. Чтобы не перегенерировать на повторных сохранениях и не
  возвращать снятый пользователем тег, фронт запускает поток генерации только
  когда слово реально добавилось впервые (его `id` не было в прошлом списке).
- Бэкенд страхует дважды: `build_word_tag_prompt` возвращает `None`, а
  `apply_generated_tags` возвращает текущие теги без изменений, если у слова уже
  есть теги.

### Команда `build_word_tag_prompt`

```
build_word_tag_prompt(wordId: String) -> Result<Option<String>, String>
```

`#[tauri::command(rename_all = "camelCase")]`. Шаги:
1. Найти слово по `wordId`. Нет слова → `invalid-saved-word`.
2. Если у слова уже есть теги → `Ok(None)` (skip).
3. Иначе собрать промпт из `display_word` + `first_meaning` + `language_name`
   (значение русскоязычное — якорит ответ на русский) с жёсткой инструкцией:
   вернуть 1–2 тематические категории по-русски, нижним регистром, по одному-два
   слова, формат — JSON-массив строк, без пояснений. Вернуть `Ok(Some(prompt))`.

Сборка промпта — отдельная чистая функция `build_prompt(word: &SavedWord) -> String`
(тестируется на присутствие слова/значения в тексте).

### Команда `apply_generated_tags`

```
apply_generated_tags(wordId: String, raw: String) -> Result<Vec<String>, String>
```

`#[tauri::command(rename_all = "camelCase")]`. Шаги:
1. Найти слово по `wordId`. Нет слова → `invalid-saved-word`.
2. Если у слова уже есть теги → вернуть их без изменений (skip-страховка).
3. `parse_theme_tags(&raw)` → до 2 нормализованных тегов.
4. Вставить каждый тег тем же путём, что `add_word_tag_in_state`
   (idempotent `ON CONFLICT(word_id, tag) DO NOTHING`, та же валидация).
5. Вернуть обновлённый `list_word_tags_in`.

Пустой/мусорный `raw` → парсер вернёт пусто → вставлять нечего → вернётся текущий
список тегов слова (для свежего слова — пустой). Ошибок не порождаем.

### Парсинг ответа модели

Отдельная **чистая** функция:

```
parse_theme_tags(raw: &str) -> Vec<String>
```

- Сначала пробуем прочитать как JSON-массив строк; если не вышло — фолбэк на
  разбиение по запятым и переводам строк.
- Каждый кандидат прогоняем через существующий `normalize_tag` (trim + lowercase,
  ≥1 буквенно-цифрового символа, лимит 40 символов по `chars().count()`) — мусор,
  пустышки и пунктуация отсекаются той же логикой, что для ручных тегов.
- Дедуп по нормализованному ключу.
- Обрезка до **2** тегов.
- Итоговый `tag_display` для авто-тегов = нормализованный (строчный) вид.

## Фронт и UI-поведение

### Доступность (один раз при старте)

`useEffect` на маунте: динамический импорт `tauri-plugin-apple-intelligence-api`,
вызов `availability()`, в состояние пишется `wordTaggerAvailable: boolean`
(`status.available`). Любая ошибка/reject → `false`. Значение также держим в
`ref`, чтобы триггер не пересоздавал колбэк сохранения.

### Триггер (фоновый поток генерации)

В `use-video-app.ts`, в `handleToggleSavedWord`, после успешного `save_word` и
**только в ветке нового слова** (не было `existingWord`), если
`wordTaggerAvailableRef.current` — запускаем `void generateWordTags(savedWord.id)`.
Сохранение и появление карточки не ждут инференс.

`generateWordTags(wordId)`:
1. Пометить `wordId` в `generatingTagWordIds` (для индикатора и блокировки
   редактора тегов).
2. `const prompt = await invoke<string | null>("build_word_tag_prompt", { wordId })`;
   если `null` — выходим (skip).
3. `const raw = await generate(prompt)` (JS-вызов плагина).
4. `const tags = await invoke<string[]>("apply_generated_tags", { wordId, raw })`.
5. Если `tags.length > 0` → `setSavedWords(... { ...word, tags })`;
   `savedWordsMutatedRef.current = true`.
6. Любая ошибка на шагах 2–4 → молча проглатываем (авто-теги — бонус).
7. `finally` → убрать `wordId` из `generatingTagWordIds`.

### Pending-состояние

Пока `wordId` в `generatingTagWordIds`, в зоне тегов карточки — ненавязчивый
индикатор «подбираю теги…» в стиле Змейки 2, и редактор тегов слова заблокирован
(объединяем `generatingTagWordIds` с существующим `tagPendingWordIds` для
`disabled`). По резолву индикатор гаснет; непустой результат добавляет чипы с тем
же `animate`-входом.

### Без мерцания на не-macOS

Индикатор и весь поток генерации запускаются только при
`wordTaggerAvailable === true`. На не-macOS флаг `false`, поведение фронта = «как
будто фичи нет».

### Ручные теги и фильтр — без изменений

Авто-теги попадают в тот же набор, поэтому сразу участвуют в `collectTagOptions`,
фильтре (OR) и автоподсказках. Снять авто-тег можно тем же крестиком. Поскольку
`origin` не храним и генерация идёт только при первом сохранении, снятый авто-тег
повторно не нагенерится.

## Тестирование

Бэкенд (`saved_words.rs` / новый модуль, in-memory SQLite, без живого AI):
- `parse_theme_tags`: JSON-массив строк парсится; фолбэк на запятые/переводы
  строк; мусор/пустышки/пунктуация отсекаются `normalize_tag`; дедуп по ключу;
  обрезка до 2; теги длиннее 40 отбрасываются.
- `build_prompt`: содержит `display_word` и `first_meaning`.
- `build_word_tag_prompt`: нет слова → `invalid-saved-word`; слово с тегами →
  `None`; свежее слово → `Some(prompt)`.
- `apply_generated_tags`: вставляет распарсенные теги и возвращает их;
  идемпотентность (повтор того же ответа не дублирует); слово с тегами → теги не
  меняются (skip); нет слова → `invalid-saved-word`; пустой/мусорный `raw` →
  пустой список без ошибки.
- Каскадное удаление при удалении слова — уже покрыто, регрессий не вводим.

Живой инференс не тестируем (гейтится железом: macOS 26 + Apple Silicon + Apple
Intelligence). В тестах фронта `generate` мокается.

Фронт (React Testing Library, мок `invoke` и мок модуля плагина):
- При первом сохранении слова и `availability().available === true` вызываются
  `build_word_tag_prompt` → `generate` → `apply_generated_tags`; по возврату
  непустого списка чипы появляются на карточке.
- Pending-индикатор показывается во время генерации и гаснет по резолву.
- `apply_generated_tags` вернул пусто → индикатор гаснет, теги не добавлены,
  ошибки нет.
- `build_word_tag_prompt` вернул `null` → `generate` не вызывается.
- `availability().available === false` → ни одного из трёх вызовов, нет
  индикатора и мерцания; ручные теги работают.
- Повторное сохранение того же слова **не** запускает генерацию.
- Ошибка `generate` → проглатывается, ошибки в панели нет, индикатор гаснет.
- Авто-тег участвует в фильтре и снимается крестиком (переиспользует тесты
  тег-механики).

## Открытые мелочи (решены по умолчанию)

- Точная строка permission плагина и git-ref/версия крейта сверяются по README
  плагина на момент реализации (early release, версия не закреплена).
- `generate(prompt)` зовём без options — длину и формат задаём текстом промпта,
  чтобы не зависеть от точного именования полей `GenerationOptions` в JS.
- Если модель вернёт тег на латинице/иностранном, он пройдёт валидацию и попадёт
  в набор; для MVP приемлемо (промпт просит русский, `first_meaning` якорит).

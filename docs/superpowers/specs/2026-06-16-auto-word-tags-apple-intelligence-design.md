# Авто-теги для сохранённых слов через Apple Intelligence — дизайн

Дата: 2026-06-16

## Цель

Автоматически подбирать **тематические** теги (тема/домен: еда, спорт, право,
эмоции и т.п.) для сохранённого слова, используя локальную модель Apple через
`tauri-plugin-apple-intelligence`. Это надстройка над существующей системой тегов
([[2026-06-16-word-tags-design]]): теги остаются единым набором, авто-теги не
отличаются от ручных, всё уже имеющееся (фильтр, автоподсказки, снятие,
каскадное удаление) переиспользуется без изменений.

## Решения (зафиксировано на брейншторме)

- **Что в тегах:** только тематические категории (тема/домен), 1–2 тега на слово,
  по-русски, нижним регистром. Часть речи/уровень/регистр — вне скоупа (часть речи
  и так есть в словарных данных).
- **Когда:** автоматически в фоне при первом сохранении слова. Без кнопок и
  ручной перегенерации.
- **Связь с ручными тегами:** один общий набор, авто-теги неразличимы от ручных.
  `origin` не храним.
- **Платформа:** фича доступна только на macOS (Apple Intelligence). На
  Windows/Android — тихий no-op; ручные теги работают везде.

## Скоуп

В скоупе:
- Новая бэкенд-команда `generate_word_tags`, вызывающая Foundation Models через
  плагин, парсящая ответ в 1–2 русских тематических тега и вставляющая их в
  существующую таблицу `word_tags`.
- Чистая функция парсинга/нормализации ответа модели.
- Фоновый триггер на фронте после первого сохранения слова, pending-индикатор,
  мерж тегов в карточку.
- Лёгкий флаг доступности таггера, чтобы на не-macOS не было лишнего pending.

Вне скоупа:
- `origin`-различение авто/ручных тегов, визуальная маркировка авто-тегов.
- Ручная перегенерация, кнопка «подобрать теги», генерация из попапа сохранения.
- Перегенерация при повторном сохранении слова.
- Облачные модели/фолбэк-провайдеры. Только локальная Apple-модель.
- Теги уровня (CEFR), части речи, регистра/стиля.
- Любые изменения плеера, второй строки субтитров, попапа сохранения.

## Архитектура

Выбран вариант **A**: вся AI-логика и парсинг живут в бэкенде, рядом с хранилищем
тегов. Отклонены: B (фронт зовёт JS-API плагина напрямую — N запросов, AI-логика
расползается в UI, хуже тестируется) и C (генерация внутри `save_word` синхронно —
блокирует быстрый CRUD на время инференса).

Фронт после успешного первого сохранения слова в фоне вызывает
`generate_word_tags` и подмешивает результат в карточку.

## Данные и бэкенд

### Платформенный гейтинг

В `src-tauri/Cargo.toml` плагин — только под macOS:

```toml
[target.'cfg(target_os = "macos")'.dependencies]
tauri-plugin-apple-intelligence = "<актуальная версия>"
```

Регистрация плагина в `lib.rs` и «настоящая» команда — под
`#[cfg(target_os = "macos")]`. Для остальных таргетов компилируется параллельная
заглушка команды с той же сигнатурой, возвращающая пустой результат, и
`word_tagger_available()`, возвращающая `false`. Так фронт всегда может звать
команды, а поведение «фичи нет» обеспечено на уровне компиляции, без рантайм-
проверок ОС на фронте.

### Хранение

Отдельной схемы нет. Авто-теги — обычные строки в существующей `word_tags`,
вставляются тем же кодом, что и ручные теги. `origin` не храним (решение «один
набор, неразличимы»). Следствие: фильтр, автоподсказки, снятие крестиком и
каскадное удаление при удалении слова работают для авто-тегов автоматически, без
изменений в этих местах.

### Когда генерируем

Только при **первом** сохранении нового слова:
- `save_word` — это upsert. Чтобы не перегенерировать на каждое повторное
  сохранение и не возвращать тег, который пользователь снял, фронт вызывает
  генерацию только когда слово реально добавилось впервые (его `id` не было в
  прошлом списке `savedWords`).
- Бэкенд дополнительно страхует: если у слова уже есть теги — генерация их не
  трогает и возвращает текущий список как есть.

## Команда `generate_word_tags`

Сигнатура (macOS):

```
generate_word_tags(wordId: String) -> Result<Vec<String>, String>
```

`#[tauri::command(rename_all = "camelCase")]`, как у соседних команд тегов.

Шаги:
1. Найти слово по `wordId` в `saved_words`. Нет слова → `invalid-saved-word`.
   Уже есть теги → вернуть их без изменений (skip-страховка).
2. Собрать промпт из `display_word` + `first_meaning` + `language_name`.
   `first_meaning` русскоязычное (из ruwiktionary) — это якорит ответ на русский.
3. Вызвать Foundation Models через плагин с жёсткой инструкцией: вернуть 1–2
   тематические категории по-русски, нижним регистром, по одному-два слова каждая,
   формат — JSON-массив строк, без пояснений.
4. Распарсить и нормализовать через `parse_theme_tags` (см. ниже).
5. Вставить каждый итоговый тег тем же путём, что `add_word_tag_in_state`
   (idempotent `ON CONFLICT(word_id, tag) DO NOTHING`, та же валидация). Вернуть
   обновлённый `list_word_tags_in`.

Вызов плагина изолируется за тонкой границей (отдельная функция/трейт), чтобы
парсер и вставка тестировались без живого инференса.

### Парсинг ответа модели

Отдельная **чистая** функция:

```
parse_theme_tags(raw: &str) -> Vec<String>
```

- Сначала пробуем прочитать как JSON-массив строк; если не вышло — фолбэк на
  разбиение по запятым и переводам строк.
- Каждый кандидат прогоняем через существующий `normalize_tag` (trim + lowercase,
  требование ≥1 буквенно-цифрового символа, лимит 40 символов по `chars().count()`)
  — мусор, пустышки и пунктуация отсекаются той же логикой, что для ручных тегов.
- Дедуп по нормализованному ключу.
- Обрезка до **2** тегов.
- `tag_display` для авто-тегов = нормализованный (строчный) вид, чтобы чипы
  выглядели единообразно (модель и так просим отвечать строчными).

### Деградация по ошибкам

AI недоступен / инференс упал / ответ не распарсился в валидные теги → команда
возвращает **пустой список**, а не ошибку. Авто-теги — бонус, их отсутствие не
должно выглядеть как сбой. Реальные ошибки стора (`saved-words-unavailable`)
пробрасываются как обычно.

### Флаг доступности

```
word_tagger_available() -> bool
```

`true` только на macOS с доступным Apple Intelligence; на остальных таргетах
заглушка возвращает `false`. Используется фронтом, чтобы не показывать pending
там, где генерации не будет.

## Фронт и UI-поведение

### Триггер

В `App.tsx`, в существующем `handleToggleSavedWord`, после успешного `save_word`
и **только если слово добавилось впервые** (его `id` не было в прошлом списке),
в фоне вызываем `invoke("generate_word_tags", { wordId })`. Сохранение слова и
появление карточки не ждут инференс — карточка показывается сразу, как сейчас.

### Pending-состояние

Пока генерация идёт, в зоне тегов карточки — ненавязчивый индикатор
«подбираю теги…» в стиле Змейки 2. Переиспользуем существующий
`tagPendingWordIds`-механизм. По резолву:
- Непустой результат → теги мержатся в `tags` слова (без дублей), индикатор
  гаснет, чипы появляются с тем же `animate`-входом, что и обычные чипы.
- Пустой результат → индикатор гаснет, ничего не добавилось (нормальный исход на
  Windows/Android и при недоступном AI).

### Без мерцания на не-macOS

При старте один раз читаем `word_tagger_available()` в состояние. Pending-
индикатор показываем только когда таггер доступен. На не-macOS флаг `false`, и
поведение фронта = «как будто фичи нет» (теги по приходу всё равно подмешались бы,
но команда возвращает пусто мгновенно).

### Ручные теги и фильтр — без изменений

Авто-теги попадают в тот же набор, поэтому сразу участвуют в `collectTagOptions`,
фильтре (OR-семантика) и автоподсказках. Снять авто-тег можно тем же крестиком.
Поскольку `origin` не храним и генерация идёт только при первом сохранении,
снятый авто-тег повторно не нагенерится.

## Тестирование

Бэкенд (`saved_words.rs` / новый модуль, in-memory SQLite, без живого AI):
- `parse_theme_tags`: JSON-массив строк парсится; фолбэк на запятые/переводы
  строк; мусор/пустышки/пунктуация отсекаются `normalize_tag`; дедуп по ключу;
  обрезка до 2; теги длиннее 40 отбрасываются.
- Вставка результата идёт тем же путём, что ручные теги: идемпотентность (повтор
  не дублирует), каскадное удаление при удалении слова (уже покрыто — регрессий
  не вводим).
- Skip-страховка: для слова с уже существующими тегами генерация их не трогает.
- Не-macOS заглушка: команда возвращает пустой список; `word_tagger_available`
  → `false`.

Живой инференс не тестируем — он гейтится железом (macOS 26 + Apple Silicon +
Apple Intelligence). Вызов плагина изолирован за тонкой границей; тестируются
парсер и вставка.

Фронт (React Testing Library, мок `invoke`):
- При первом сохранении слова вызывается `generate_word_tags`; по возврату
  непустого списка чипы появляются на карточке.
- Pending-индикатор показывается во время генерации (когда
  `word_tagger_available` = true) и гаснет по резолву.
- Пустой результат → индикатор гаснет, теги не добавлены, ошибки нет.
- `word_tagger_available` = false → нет pending-индикатора и мерцания; ручные
  теги работают.
- Повторное сохранение того же слова **не** запускает генерацию.
- Авто-тег участвует в фильтре и снимается крестиком (переиспользует тесты
  тег-механики).

## Затрагиваемые файлы

Бэкенд:
- `src-tauri/Cargo.toml` — таргет-зависимость плагина под macOS.
- `src-tauri/src/lib.rs` — регистрация плагина и команд под
  `#[cfg(target_os = "macos")]`, заглушки для остальных таргетов.
- `src-tauri/src/saved_words.rs` (или новый `word_tagger.rs`) — команда
  `generate_word_tags`, чистая `parse_theme_tags`, `word_tagger_available`,
  изоляция вызова плагина, тесты.

Фронтенд:
- `src/lib/saved-words/types.ts` — контракт команды/флага при необходимости.
- `src/App.tsx` — фоновый триггер после первого сохранения, флаг доступности,
  мерж тегов, pending.
- `src/components/saved-words-panel.tsx` — pending-индикатор «подбираю теги…» в
  зоне тегов карточки.

## Открытые мелочи (решены по умолчанию)

- Версия плагина фиксируется на момент реализации (актуальный релиз, где доступен
  нужный API генерации текста). Структурированный вывод в плагине ещё не релизнут
  — поэтому парсим текстовый ответ сами через `parse_theme_tags`.
- Если модель вернёт тег на латинице/иностранном, он всё равно пройдёт валидацию и
  попадёт в набор; для MVP приемлемо (промпт просит русский, `first_meaning`
  якорит на русский).

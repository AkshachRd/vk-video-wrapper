# Теги для сохранённых слов — дизайн

Дата: 2026-06-16

## Цель

Дать возможность помечать сохранённые слова тегами и фильтровать список «Слова»
по тегам. Теги — лёгкий способ организовать накопившийся словарь (по части речи,
уровню, теме и т.п.).

## Скоуп

В скоупе:
- Гибридные теги: вводятся свободным текстом, каждый введённый тег попадает в
  общий набор и дальше переиспользуется через автоподсказки.
- Назначение и снятие тегов только в панели «Слова» (на карточке слова).
- Фильтрация списка по тегам с семантикой OR (несколько выбранных тегов
  расширяют подборку).

Вне скоупа (MVP):
- Назначение тегов из попапа сохранения слова — попап не трогаем.
- Глобальный менеджер тегов (переименование/удаление тега во всех словах сразу).
  Тег существует, пока им помечено хотя бы одно слово; снятие с последнего слова
  убирает тег из общего набора и из фильтра. Переименование — через снять/добавить.
- Цвета/иконки тегов — оформление монохромное (тема «Змейка 2»).
- Семантика AND в фильтре.

## Данные и бэкенд

### Таблица `word_tags`

Отдельной таблицы тегов нет — это даёт правило «тег существует, пока есть слово»
автоматически.

```sql
CREATE TABLE IF NOT EXISTS word_tags (
  word_id       TEXT    NOT NULL,
  tag           TEXT    NOT NULL,
  tag_display   TEXT    NOT NULL,
  created_at_ms INTEGER NOT NULL,
  UNIQUE(word_id, tag)
);
```

- `word_id` совпадает с `saved_words.id` (формат `"<language>:<normalized_word>"`,
  например `"de:haus"`).
- `tag` — нормализованный ключ: `trim` + `lowercase`.
- `tag_display` — как ввёл пользователь (после `trim`).
- Глобальный набор тегов = `SELECT DISTINCT tag` по всей таблице.
- Удаление слова удаляет его строки в `word_tags` (явным `DELETE ... WHERE
  word_id = ?` в `remove_saved_word_in_state`, без надежды на FK-каскад).
- При повторном сохранении слова (`save_word`, upsert) `id` не меняется, теги
  сохраняются.

Миграция добавляется к существующему `MIGRATION` в `saved_words.rs`
(`execute_batch`, идемпотентно через `IF NOT EXISTS`).

### Нормализация и валидация тега

- Ключ: `trim` + `lowercase` (как `normalize_word`, но без требования к буквам —
  достаточно непустоты после trim).
- Отклоняем теги, пустые или состоящие только из пунктуации/пробелов (тот же
  принцип, что и для слов: должен быть хотя бы один алфавитно-цифровой символ).
  Ошибка — новый вид `SavedWordsError::InvalidTag` с kind `invalid-tag`.
- Лимит длины — 40 символов по `chars().count()`; длиннее — `InvalidTag`.

### Изменения контракта `SavedWord`

`SavedWord` (Rust и `src/lib/saved-words/types.ts`) получает поле:

```
tags: Vec<String>   // tag_display, порядок по created_at_ms ASC
```

`list_saved_words_in_state` отдаёт теги сразу (через отдельный запрос по всем
словам или JOIN с группировкой), чтобы фронт не делал N запросов. Порядок тегов
внутри слова — по `created_at_ms ASC`, затем по `tag` для стабильности.

### Новые Tauri-команды

- `add_word_tag(wordId: String, tag: String) -> Result<Vec<String>, String>` —
  вставляет строку (idempotent через `ON CONFLICT(word_id, tag) DO NOTHING`),
  возвращает обновлённый список `tag_display` слова. Если слова с таким `word_id`
  нет в `saved_words`, команда возвращает `invalid-saved-word` и ничего не пишет
  (защита от orphan-строк по итогу код-ревью; фронт такие случаи и так не
  порождает — тег ставится только на существующую карточку).
- `remove_word_tag(wordId: String, tag: String) -> Result<Vec<String>, String>` —
  удаляет строку по `(word_id, normalize(tag))`, возвращает обновлённый список
  тегов слова.

Обе команды используют `rename_all = "camelCase"` для аргументов (как
`remove_saved_word`). При недоступном сторе возвращают `saved-words-unavailable`.

### Фильтрация — на фронте

Отдельной команды `list_tags` нет. Глобальный набор тегов, их счётчики и
фильтрация считаются на фронте из уже загруженных `savedWords[].tags`.

## UI и поведение (панель «Слова»)

### Карточка слова

Под строкой значения (`firstMeaning`) добавляется зона тегов:

- Чипы текущих тегов — мелкие монохромные пилюли в стиле Змейки 2. На каждом чипе
  крестик снятия, появляется по hover/focus карточки (как кнопка удаления слова).
- Аффорданс «+ тег»: по клику разворачивается в инлайн-инпут с автоподсказками из
  глобального набора (фильтр по вводу, регистронезависимо). Enter или выбор
  подсказки → тег добавлен; Esc или blur → инпут сворачивается без добавления.
  Можно ввести новый тег или выбрать существующий (гибрид).
- Дубликат тега на одном слове игнорируется (гарантировано `UNIQUE` + idempotent
  insert; на фронте новый чип просто не дублируется).

### Фильтр над списком

Если в наборе есть хотя бы один тег — над списком показывается строка чипов:

- Клик по чипу — toggle выбора. Выбранные подсвечены (заливка `ink`),
  невыбранные — контур.
- Несколько выбранных → OR: слово видно, если у него есть хотя бы один из
  выбранных тегов.
- Кнопка «Сбросить» появляется, когда выбран хотя бы один тег.
- Счётчик в шапке панели показывает число видимых слов; если фильтр что-то скрыл —
  рядом мелко «N из M».
- Пустой результат → строка «Нет слов с выбранными тегами».
- Если выбранный тег исчез из набора (снят с последнего слова) — он убирается из
  выбора фильтра автоматически.

### Поведение записи (оптимистичное)

В духе текущего кода (`handleToggleSavedWord`):

- Добавление/снятие тега локально обновляет `tags` нужного слова сразу; на
  затронутом чипе/инпуте — pending-состояние (блокировка повторного клика).
- При ошибке команды — откат локального изменения и тихое сообщение в панели
  (через существующий `savedWordsPanelError`).
- При `savedWordsUnavailable` зоны тегов и строка фильтра не показываются.

### Без изменений

Попап сохранения слова, вторая строка субтитров и любой код плеера не
затрагиваются.

## Тестирование

Бэкенд (`saved_words.rs`, in-memory SQLite):
- Миграция создаёт таблицу `word_tags`.
- `add_word_tag` добавляет тег и возвращает список; повтор того же тега
  идемпотентен (нет дубля, нет ошибки).
- `remove_word_tag` снимает тег; снятие последнего убирает его из
  `SELECT DISTINCT tag`.
- Удаление слова (`remove_saved_word_in_state`) каскадно удаляет его строки в
  `word_tags`.
- `list_saved_words_in_state` отдаёт теги в поле `tags`, порядок по `created_at_ms`.
- Нормализация: `"Глаголы"` и `"глаголы"` — один тег; пустой/пунктуационный тег и
  тег длиннее 40 символов → `invalid-tag`.
- Недоступный стор → `saved-words-unavailable` для обеих новых команд.

Фронтенд (React Testing Library, мок `invoke`):
- На карточке можно добавить тег через инлайн-инпут; чип появляется.
- Автоподсказки предлагают существующие теги из набора.
- Снятие тега крестиком убирает чип.
- Клик по чипу фильтра сужает список; несколько чипов работают по OR.
- «Сбросить» очищает фильтр; счётчик «N из M» при активном фильтре.
- Пустой результат фильтра показывает соответствующую строку.
- Ошибка команды откатывает оптимистичное изменение и показывает сообщение.
- При `savedWordsUnavailable` теги и фильтр не отображаются.

## Открытые мелочи (решены по умолчанию)

- При расхождении регистра `tag_display` между словами для глобального чипа
  фильтра берётся любой согласованный вариант (например с наибольшим
  `created_at_ms`). Приемлемо для MVP.
- Сортировка чипов фильтра — по алфавиту нормализованного ключа.
